# Programming Brain Acceptance Contract

This contract defines completion for the senior software-engineer brain. A
model statement, an aggregate accuracy estimate, or one successful project is
not completion evidence.

## Production brain invariants

- Every forward corpus row is either admitted or represented by an unresolved,
  exact half-open quarantine interval.
- Every quarantine interval is transactionally replayed and resolved; no
  unresolved interval or replay marker remains.
- The final `.wbrain` passes foundational retention, trained and unseen code
  execution, enterprise, polyglot, OOV-honesty, causal integration, live
  failure/repair learning, read-only topology, mobile-runtime, and cold/warm
  latency gates.
- Final neuron-wise sleep and checkpoint report zero resident terminals without
  changing learned topology. Inference deserializes only the relevant neural
  scope.

## Deterministic 1,000-task obstacle course

Build a versioned manifest with exactly 1,000 distinct held-out tasks. Every
task has an immutable ID, capability family, language/toolchain version,
prompt, fixtures, deterministic validator, timeout, and provenance. Use these
fixed family counts:

| Capability family | Tasks |
|---|---:|
| Requirements and API contracts | 80 |
| Algorithms and data structures | 70 |
| Validation, parsing, and serialization | 70 |
| Databases, migrations, and transactions | 80 |
| HTTP APIs, authentication, and application security | 90 |
| Concurrency, asynchronous work, and distributed coordination | 80 |
| Testing, debugging, repair, and refactoring | 100 |
| Reliability, observability, and performance | 80 |
| CI/CD, containers, packaging, and platform engineering | 70 |
| Frontend state, UX, and accessibility | 70 |
| Polyglot, native, and interoperability work | 70 |
| Architecture, multi-file change, and integration | 70 |
| Scientific computing, 3D geometry, and robotics | 70 |
| **Total** | **1,000** |

Validators must compile or parse generated code and execute its behavioral
contract inside bounded isolated workspaces. Where relevant they also inspect
tests, migrations, schemas, concurrency behavior, security properties,
performance ceilings, accessibility, reproducible builds, and repository
changes. Identifier or formatting checks cannot substitute for behavior.

The held-out obstacle prompts and fixtures must never become training rows.
On failure, cluster cases by the smallest causal capability. Repair with either
an architecture correction or separately sourced curriculum whose license and
provenance are recorded in an SPDX-compatible manifest. Prefer existing local
corpora. New content must permit the intended training and redistribution use;
do not infer a license from public availability. After each repair, rerun the
failed family, protected retention, and then the complete frozen 1,000-task
course. Admission requires `1000/1000`, with no skipped, manually waived,
network-dependent, flaky, or validator-error cases.

## Multi-Scale Robot World capstone

Brand Dozer and C0D3R V2 must use the qualified brain to complete the existing
Multi-Scale Robot World specification. Review the delivered product
independently; never accept its own completion claim. At minimum, evidence must
cover:

- a usable, coherent 3D robot-building world rather than a static mock-up;
- parametric robot parts, assemblies, transforms, constraints, joints,
  actuators, sensors, materials, and reusable designs across meaningful scales;
- explicit real-world units and credible rigid-body behavior for gravity,
  mass/inertia, collisions, friction, damping, joints, motors, and constraints,
  with analytical or reference scenarios checking the physics;
- deterministic save/load, versioned project data, undo/redo, useful error
  recovery, and no loss of the user's design;
- fabrication export appropriate for 3D printing, including scale, tolerances,
  manifold/watertight geometry checks, minimum-wall and clearance diagnostics,
  orientation/support guidance, and validated STL/3MF or equivalent artifacts;
- professional interaction design, accessibility, responsive performance,
  security, tests, documentation, and a clean first-run workflow;
- browser, backend, build, integration, and representative visual/interaction
  verification against the full specification.

“World-class” is judged by the integrated product quality and these observed
behaviors, not feature-name presence. Any broken critical workflow, fake
physics, non-printable output, placeholder implementation, unverified claim,
or substantial specification gap returns the project to the brain's
failure/repair learning loop.

## Machine completion evidence

The Codex watchdog may stop only when
`runtime/programming-brain-codex-watch/objective-complete.json` contains all of
the following and each referenced report exists and passes its own checks:

```json
{
  "passed": true,
  "production_brain": {"passed": true, "report": "..."},
  "obstacle_course": {"passed": 1000, "total": 1000, "report": "..."},
  "brain_selectors": {"passed": true, "report": "..."},
  "capstone": {"passed": true, "independently_verified": true, "report": "..."}
}
```

Before publishing that marker, perform a requirement-by-requirement audit from
current artifacts, tests, runtime behavior, and repository state. Missing or
indirect evidence means incomplete.
